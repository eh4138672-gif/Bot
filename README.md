# בוט תקנון מכללה – מערכת RAG

מערכת שעונה על שאלות של סטודנטיות לגבי התקנון של מכללה (דמיונית) בשם "מכללת אופק להנדסה ומדעים".
הבוט עונה **רק** מתוך מסמכי התקנון, מציג את הקטעים שעליהם התשובה מבוססת, וכשאין תשובה בתקנון הוא אומר את זה ולא ממציא.

## בסיס הידע
בתיקייה `data/` יש 11 מסמכים עם כ-75 סעיפים ממוספרים:

| קובץ | תוכן |
|---|---|
| `01_תקנון_בחינות.md` | מועדי בחינות, מועד מיוחד, התנהלות בבחינה, פרסום ציונים |
| `02_ערעורים_על_ציונים.md` | נוהל ערעור, מועדים, ערעור שני, אגרה |
| `03_רישום_וביטול_קורסים.md` | סבבי רישום, תקופת שינויים, ביטול קורס, קורסי קדם |
| `04_נוכחות_והתנהגות.md` | חובת נוכחות, איחורים, יושר אקדמי, שימוש ב-AI |
| `05_שכר_לימוד_ומלגות.md` | שכר לימוד, תשלומים, הפסקת לימודים, מלגות |
| `06_עבודות_ופרויקט_גמר.md` | הגשת עבודות, איחורים, פרויקט גמר |
| `07_ספרייה.md` | שעות פתיחה, השאלה, קנסות, חדרי לימוד, מאגרי מידע |
| `08_מעונות_וחניה.md` | מעונות (זכאות, מחיר, כללים), חניה, שאטל ותחבורה |
| `09_שירותי_מחשוב.md` | חשבון משתמש, סיסמה, Wi-Fi ו-VPN, תוכנות, מעבדות, תמיכה |
| `10_דיקנט_ותמיכה.md` | דיקנט, התאמות, שיעורי עזר, ייעוץ פסיכולוגי, מילואים, אגודה |
| `11_לוח_שנה_וזכאות_לתואר.md` | תאריכי סמסטרים, חופשות, סמסטר קיץ, תנאי זכאות לתואר, הצטיינות |

אפשר להוסיף מסמכים לתיקייה (קבצי `.md` או `.txt`) ולהריץ שוב את `ingest.py`.

## ארכיטקטורה

```
שלב הכנה (ingest.py) – רץ פעם אחת:
  data/*.md → SimpleDirectoryReader
            → MarkdownNodeParser (כל סעיף בתקנון = chunk)
            → SentenceSplitter (מפצל רק סעיף ארוך מ-1024 טוקנים, חפיפה 100)
            → metadata: מספר סעיף, נושא המסמך
            → OpenAI text-embedding-3-large → ChromaDB (נשמר בתיקייה chroma_db/)

שלב שאלה (rag.py + app.py) – בכל שאלה:
  שאלה → הרחבת שאלה עם gpt-4o-mini (אפשר לכבות בממשק)
       → השאלה מזכירה "סעיף X.Y"? → סינון לפי metadata של הסעיף
       → אחרת: חיפוש cosine ב-ChromaDB (Top K = 4) + זריקת קטעים מתחת ל-0.40
       → אין קטעים? מחזירים "לא מצאתי מידע" בלי לפנות ל-LLM
       → יש קטעים? gpt-4o-mini כותב תשובה רק מהקטעים, או אומר שאין תשובה
       → תשובה + מקורות + ציוני דמיון + שאילתת החיפוש + ספירת טוקנים
```

| קובץ | תפקיד |
|---|---|
| `config.py` | כל ההגדרות וההחלטות הטכנולוגיות במקום אחד |
| `ingest.py` | טעינה, חלוקה ל-chunks לפי מבנה, metadata, יצירת embeddings ושמירה ב-ChromaDB |
| `rag.py` | הרחבת שאלה, אחזור (כולל סינון לפי סעיף), יצירת תשובה, רשימת נושאי המאגר, ספירת טוקנים |
| `app.py` | ממשק צ'אט ב-Streamlit |
| `run_tests.py` | הרצת סט שאלות קבוע (עם הרחבת שאלה ובלעדיה) ושמירת התוצאות ב-`examples.md` |

## הבחירות הטכנולוגיות ולמה

| החלטה | בחירה | נימוק |
|---|---|---|
| ספריית RAG | LlamaIndex | דרישת התרגיל. מספקת Reader, Node Parser, Retriever ו-Synthesizer מוכנים |
| Vector DB | ChromaDB | נלמד בכיתה, רץ מקומית בלי שרת, נשמר על הדיסק, תומך בסינון metadata, ויש לו חיבור מוכן ל-LlamaIndex |
| מודל Embeddings | `text-embedding-3-large` (OpenAI) | התחלתי עם `3-small`, אבל בעברית הוא פספס סעיפים רלוונטיים (ראו בעיה 3). `3-large` עולה $0.13 למיליון טוקנים, ובניית המאגר כולו עולה פחות מסנט |
| מודל תשובות | `gpt-4o-mini` (OpenAI), `temperature=0` | זול, מהיר ומספיק טוב לניסוח תשובה מקטעים נתונים. `temperature=0` מקטין המצאות |
| חלוקה ל-chunks | לפי מבנה המסמך (`MarkdownNodeParser`) ואז לפי טוקנים (`SentenceSplitter`) | חלוקה לפי משמעות (Semantic) יקרה, כי צריך embedding לכל משפט. בתקנון המבנה כבר קיים: כל סעיף עוסק בנושא אחד, ולכן כל סעיף הוא chunk. רק סעיף ארוך מדי מפוצל לפי טוקנים |
| גודל chunk | עד 1024 טוקנים | בעברית כל תו הוא בערך טוקן (ראו בעיה 2), ולכן 1024 טוקנים מספיקים לסעיף שלם |
| חפיפה | 100 טוקנים (~10%) | רלוונטית רק לסעיף ארוך שמפוצל. שומרת על הקשר בין החלקים בלי לנפח את האינדקס |
| Top K | 4 | מספיק לשאלה שהתשובה עליה מפוזרת בכמה סעיפים, בלי להעמיס על המודל רעש וטוקנים |
| צורת חיפוש | דמיון קוסינוס + סינון metadata לפי מספר סעיף | קוסינוס הוא המדד שהמודלים של OpenAI מותאמים אליו. חיפוש סמנטי לא מבחין בין מספרי סעיפים, ולכן שאלה על סעיף מסוים מסוננת לפי metadata (ראו בעיה 4) |
| סף דמיון | 0.40 | זורק רק קטעים שממש לא קשורים. ההחלטה אם יש תשובה עוברת ל-LLM (ראו בעיה 5) |
| הרחבת שאלה | פעילה כברירת מחדל, אפשר לכבות בממשק | עולה קריאה נוספת ל-LLM (בערך 100 טוקנים), אבל פתרה שאלות קצרות ("מילואים") ושאלות במילים שלא מופיעות במסמך ("צ'אט GPT" לעומת "בינה מלאכותית") |
| קליינט | Streamlit | הכי פשוט לבנות צ'אט עם הצגת מקורות |

**בונוס:** בפרויקט מומש **Metadata Filtering**. כל chunk נשמר עם מספר הסעיף שלו, ושאלה על סעיף מסוים מסוננת לפי השדה הזה.

## הוראות הרצה

1. יוצרים סביבה וירטואלית ומתקינים את הספריות:
   ```bash
   py -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   ```
2. יוצרים מפתח API ב-https://platform.openai.com/api-keys, מעתיקים את `.env.example` לקובץ בשם `.env`, ושמים בו את המפתח:
   ```
   OPENAI_API_KEY=sk-...
   ```
3. בונים את ה-Vector DB (פעם אחת, ובכל פעם שמשנים מסמכים):
   ```bash
   python ingest.py
   ```
4. מריצים את הממשק:
   ```bash
   streamlit run app.py
   ```
5. (אופציונלי) מריצים את סט שאלות הבדיקה. התוצאות נשמרות ב-`examples.md`:
   ```bash
   python run_tests.py
   ```

## בעיות שנתקלתי בהן ואיך פתרתי

### בעיה 1: הסינון (NetFree) חסם את ה-API ושבר את תעודת ה-SSL
**מה קרה:** בהרצה הראשונה כל קריאה ל-OpenAI נכשלה עם `CERTIFICATE_VERIFY_FAILED: Basic Constraints of CA cert not marked critical`. הסינון מחליף את תעודת ה-SSL בתעודה משלו, ו-Python 3.13 דוחה אותה בבדיקה המחמירה שלו. אחרי שזה תוקן, השרת החזיר `418 blockByNetFree`: הכתובת `api.openai.com` שייכת לתגית "צ'אט בינה מלאכותית", שחסומה בחשבון. ניסיתי לעבור ל-Gemini, אבל גם הוא נחסם מאותה סיבה.
**הפתרון:**
- בקוד (`config.py`) הוספתי `truststore.inject_into_ssl()`, כדי ש-Python יאמת תעודות מול מאגר התעודות של Windows, שבו תעודת הסינון מותקנת.
- בהגדרות הסינון פתחתי באופן אישי את הכתובת `api.openai.com`. הגדרה אישית של כתובת גוברת על חסימת התגית.

### בעיה 2: חיתוך לפי 512 טוקנים שבר את הסעיפים, כי עברית "יקרה" בטוקנים
**מה קרה:** בבדיקות הראשונות, בשאלה "כמה פעמים מותר לי לא להגיע לתרגול?" הבוט לא מצא את סעיף 6.1 וענה תשובה חלקית. כשבדקתי מה נשלף, ראיתי ש-chunks של 512 טוקנים הכילו רק כ-450 תווים. מדדתי ומצאתי שבעברית יוצא בערך טוקן אחד לכל תו (2,225 תווים = 2,074 טוקנים), כלומר כ-5 טוקנים למילה, לעומת 1.3 באנגלית. לכן סעיפים נחתכו באמצע, והחלק השני הגיע בלי הכותרת שלו.
**הפתרון:** עברתי לחלוקה לפי מבנה המסמך. `MarkdownNodeParser` מחלק לפי כותרות, כך שכל סעיף הוא chunk אחד שלם יחד עם הכותרת שלו. את הגודל המקסימלי העליתי ל-1024 טוקנים, כך שרק סעיף ארוך מאוד מפוצל. בנוסף זרקתי chunks שהם רק כותרת בלי תוכן (כמו "פרק 1 – מועדי בחינות").

### בעיה 3: ציוני הדמיון היו כמעט זהים, והחיפוש שלף סעיפים לא קשורים
**מה קרה:** גם אחרי התיקון, בשאלה על היעדרות הציונים היו 0.55, 0.54, 0.54, והסעיף הנכון לא היה בין המובילים. כשהדפסתי את הטקסט שבאמת עובר ל-embedding, גיליתי שכמעט חצי ממנו הוא metadata שחוזר בכל chunk: שם הקובץ, נתיב הכותרות, ופעמיים "מכללת אופק להנדסה ומדעים". לכן כל הווקטורים היו דומים זה לזה.
**הפתרון:**
- הוצאתי מה-embedding את כל ה-metadata (`excluded_embed_metadata_keys`), חוץ משם נושא קצר (למשל "תקנון נוכחות והתנהגות").
- החלפתי את `text-embedding-3-small` ב-`text-embedding-3-large`, שמבין עברית טוב יותר. אחרי השינוי, שאלת ההיעדרות שולפת את סעיפי 6.1–6.3, ושאלת ביטול הקורס שולפת את 5.3 במקום הראשון. העלות של בניית המאגר כולו נשארה פחות מסנט.

### בעיה 4: חיפוש לפי מספר סעיף לא עבד, וההרחבה המציאה מספרי סעיפים
**מה קרה:** על השאלה "מה אומר סעיף 1.3?" הבוט ענה "לא מצאתי מידע". החיפוש הסמנטי שלף סעיפים מתקנון הנוכחות, כי embedding לא מבחין בין "1.3" ל-"6.3". הוספתי סינון לפי metadata של הסעיף, ואז נוצרה בעיה חדשה: מודל הרחבת השאלה הוסיף מעצמו "בהתאם לסעיף 7.3" לשאלה על ערעור, והסינון נעל את החיפוש על סעיף התשלומים.
**הפתרון:** ב-`ingest.py` כל chunk מקבל metadata עם מספר הסעיף שלו. ב-`rag.py`, אם **השאלה המקורית** של המשתמשת מזכירה "סעיף X.Y", החיפוש מסונן לפי השדה הזה (Metadata Filtering). מספר הסעיף נלקח רק מהשאלה המקורית ולא מהשאלה המורחבת, ובפרומפט של ההרחבה נאסר להוסיף מספרי סעיפים.

### בעיה 5: סף הדמיון לא הצליח להפריד בין שאלה רלוונטית לשאלה שאין עליה תשובה
**מה קרה:** (בגרסה הראשונה של המאגר, עם 6 מסמכים, לפני שנוספו מסמכי המעונות והחניה.) קבעתי סף של 0.30 כדי שהבוט לא יענה על שאלות שאין עליהן תשובה במאגר. בבדיקות, השאלה "מה שעות הפתיחה של הקפיטריה?" קיבלה 0.49 ו"יש מעונות לסטודנטיות?" קיבלה 0.57, בזמן ששאלות רלוונטיות קיבלו 0.52–0.68. הטווחים חופפים, כך שאין סף שמפריד ביניהם.
**הפתרון:** הסף ירד לתפקיד משני: 0.40, שזורק רק קטעים שממש לא קשורים. את ההחלטה אם יש תשובה קיבל ה-LLM, עם הנחיה מפורשת בפרומפט: "עני רק על סמך הקטעים... אם התשובה לא מופיעה, עני בדיוק: לא מצאתי מידע". בכל הבדיקות הבוט לא המציא תשובה לשאלה שאין עליה מידע.

### בעיה 6: הרחבת השאלה שינתה את כוונת השאלה
**מה קרה:** בגרסה הראשונה של הפרומפט נתתי למודל דוגמאות של מונחים ("ערעור, מועד ב', ביטול רישום, שכר לימוד, נוכחות"). על השאלה "מילואים" המודל החזיר שאילתה על נוכחות, ביטול רישום, ערעורים ושכר לימוד, כלומר ארבעה נושאים שהמשתמשת לא שאלה עליהם, והתשובה יצאה גרועה יותר.
**הפתרון:** הורדתי את רשימת הדוגמאות והוספתי הנחיה מפורשת: "הישארי בדיוק באותו נושא, אל תוסיפי נושאים". אחרי התיקון ההרחבה עוזרת. "מילואים" ו"מותר להשתמש בצ'אט GPT?" נענו נכון רק עם הרחבה, ובשאר השאלות היא לא פגעה. לכן היא פעילה כברירת מחדל.

### בעיה 7: המודל סירב לענות גם כשהתשובה הייתה מולו
**מה קרה:** כשהבוט עבר לשימוש אמיתי, על הרבה שאלות הוא ענה "לא מצאתי מידע". למשל, על "אפשר להגיש עבודה באיחור?" החיפוש שלף את סעיף 8.2 ("איחור בהגשה") במקום הראשון, ובכל זאת המודל ענה שאין מידע. ההנחיה "אם התשובה לא מופיעה בקטעים, עני: לא מצאתי" גרמה לו להחמיר מדי. כשהניסוח בשאלה היה שונה מהניסוח בסעיף, הוא החליט שהתשובה "לא מופיעה".
**הפתרון:** שיניתי את הפרומפט כך שיענה על סמך כל מידע שקשור לשאלה, גם אם הוא מנוסח אחרת או עונה רק על חלק ממנה. רק כשאין בקטעים שום מידע קשור, הוא עונה "לא מצאתי". אחרי השינוי בדקתי שוב את השאלות שאין עליהן תשובה (קפיטריה, מעונות, ראש המכללה, חניה, מזג אוויר, שאז עוד לא היו במאגר), וכולן עדיין קיבלו "לא מצאתי", כלומר התיקון לא גרם להמצאות.

### בעיה 8: שאלה כללית ("מה יש לך על המכללה?") קיבלה "לא מצאתי"
**מה קרה:** RAG מחפש את 4 הקטעים הכי דומים לשאלה, אבל שאלה כמו "מה יש לך על המכללה?" או "במה את יכולה לעזור?" מתייחסת למאגר כולו ולא לסעיף מסוים. אין קטע אחד שעונה עליה. בנוסף, הרחבת השאלה הפכה אותה ל"היסטוריה, מטרות ודרישות קבלה של המכללה", נושאים שלא קיימים במאגר.
**הפתרון:** בעליית המערכת נשלפת מ-ChromaDB רשימת הנושאים של כל המסמכים (שדה ה-metadata `topic`), והיא נכנסת לפרומפט עם ההנחיה "אם שואלים באופן כללי מה יש במאגר, תארי את הנושאים". אותה רשימה מוצגת גם בצד המסך תחת "על מה אפשר לשאול". בנוסף, בפרומפט של ההרחבה נוספה ההנחיה "שאלה כללית נשארת כללית". אחרי השינוי בדקתי שוב ששאלות רגילות ושאלות שאין עליהן מידע ממשיכות לעבוד כמו קודם.
